# 📘 سند تحقیق جامع — ماژول اولتراسونیک HC-SR04
### پایه‌ی دانشی برای ساخت «دوقلوی دیجیتال» (Digital Twin) سنسور

> این سند از روی دیتاشیت رسمی (Elecfreaks / SparkFun / HandsonTec)، اسناد Murata برای ترنسدیوسر، و دو پروژه‌ی معروف **ریورس‌انجینیرینگ کامل مدار داخلی** (Emil's Projects و David Pilling) تهیه شده است. هدف: داشتن مدلی که نه‌فقط «مشخصات»، بلکه «رفتار» ماژول واقعی — حتی عیب‌ها و خطاهایش — را بازتولید کند.

## ۲) مشخصات فیزیکی 🔧

| مورد | مقدار |
|---|---|
| ابعاد کل ماژول | **45mm × 20mm × 15mm** |
| وزن | **~9g** (برخی نمونه‌ها 8.5g) |
| PCB | FR-4، ضخامت ~1.6mm، ماسک آبی یا سبز |
| سوراخ‌های نصب | **4 عدد Ø1mm (M1)**، فاصله‌ی مرکز سوراخ‌ها **40mm × 15mm** |
| کانکتور | هدر ۴ پین با پیچ **2.54mm** (قابل فروبردن در بردبرد) |
| پین‌ها | ① VCC ② Trig ③ Echo ④ GND (از چپ، رو به ترنسدیوسرها) |
| ترنسدیوسرها | ۲ عدد **قطر 16mm × ارتفاع ~12mm**، بدنه‌ی آلومینیومی با مش فلزی بالایی، مُهر T (فرستنده) و R (گیرنده) |
| خازن خروجی ترنسدیوسر | ~2400 تا 2550pF ±20% |

### اجزای روی برد (نتیجه‌ی باز کردن مدار):
- **میکروکنترلر OTP**: EM78P153S (چینی) با کریستال **27MHz** (در نمونه‌های دیگر STC11 / PIC / ASIC تک‌تراشه CS100A)
- **MAX232 (U3)**: به‌عنوان چارج‌پامپ برای تولید **±10V** از 5V → درایو فرستنده با ولتاژ مؤثر **~20Vpp** (ترنسدیوسر بین دو خروجی MAX232)
- **Q2 (ترانزیستور)**: قطع/وصل تغذیه‌ی MAX232 (چون چارج‌پامپ نویزی است — فقط قبل و هنگام تابش روشن می‌شود)
- **LM324 (U2)**: اپ‌امپ چهارتایی برای زنجیره‌ی گیرنده (در نسخه‌ی P/V2: **SGM324** → پشتیبانی 3.3V و جریان کمتر)
- ترانزیستور Q1 → مقایسه‌گر با هیسترزیس

## ۴) مشخصات آکوستیک 🔊

| پارامتر | مقدار | توضیح |
|---|---|---|
| فرکانس رزونانس | **40kHz ±1kHz** | طول موج در هوا: **λ ≈ 8.5mm**، پریود: **25µs** |
| فشار صوتی (SPL) | **112dB** (≥110~115dB) | در 30cm با 10Vrms — مرجع 0dB=20µPa |
| حساسیت گیرنده | **≥ −65 ~ −67dB** | در 40kHz |
| زاویه‌ی مؤثر (Effective Angle) | **≤15°** | در برخی منابع «کون 30°» — یعنی پهنای اصلی ~±15° |
| پهنای باند | باریک (~1~2kHz، Q بالا) | به همین دلیل فقط روی رزونانس کار می‌کند |
| Beam واقعی (اندازه‌گیری تجربی) | لوب اصلی پهن‌تر از اسم؛ حساسیت با زاویه افت می‌کند | زوایای بزرگ → بازتاب گم می‌شود |

## ۵) پروتکل ارتباطی و تایمینگ دقیق ⏱️ (قلب دوقلوی دیجیتال)

### دیاگرام زمانی رسمی:
```
Trig :  ────┐┌──────┐┌──────────────────────────────
            ││ 10µs ││
            └┘      └┘
Burst(40kHz):        [تاخیر داخلی] ████████ 8 پالس (200µs)
Echo :               ┌──────────────────────────────┐
                     │ HIGH = مدت رفت‌وبرگشت صوت     │
                     └──────────────────────────────┘
                     ←—————— 38ms حداکثر (timeout) ——————→
```

### ترتیب رویدادهای داخلی (بر اساس اسکوپ‌شات ریورس‌انجینیرینگ):
1. **پالس Trig** حداقل **10µs** HIGH شود
2. MCU پس از **~10µs** آن را شناسایی و تغذیه‌ی MAX232 (چارج‌پامپ) را از طریق Q2 وصل می‌کند
3. **~248µs** طول می‌کشد تا ولتاژ ±10V پامپ بالا بیاید
4. **برست ۸ پالس 40kHz** ارسال می‌شود (مدت: **8 × 25µs = 200µs**) — هم‌زمان آستانه‌ی مقایسه‌گر گیرنده «بسته» نگه داشته می‌شود تا نویز فرستنده شنیده نشود
5. تغذیه‌ی MAX232 قطع و **پین Echo HIGH** می‌شود
6. اولین پالسِ برگشتی که از آستانه‌ی مقایسه‌گر بالا برود → **Echo LOW** می‌شود
7. عرض پالس HIGH روی Echo = زمان پرواز (ToF)

### فرمول‌ها:
```
فاصله(cm) = پالس Echo(µs) / 58        ← معادل v=340m/s
فاصله(inch) = پالس Echo(µs) / 148
فاصله(m) = پالس Echo(µs) × 340 / 2×10⁶
```

### قواعد سختِ تایمینگ (که دوقلو باید رعایت کند):
| قاعده | مقدار | پیامد |
|---|---|---|
| حداکثر عرض پالس Echo (بدون مانع) | **38ms** سپس LOW | یعنی `duration ≥ 38000µs` = «خارج از رنج» |
| حداقل فاصله بین دو Trig | **60ms** (پیشنهاد دیتاشیت) | جلوگیری از تداخل اکوی قبلی با برست بعدی |
| حداکثر نرخ خواندن عملی | ~15–16Hz | با سایکل 60ms |
| حداکثر ToF (رنج 4m) | ~23.5ms رفت‌وبرگشت | — |
| حداقل رنج (Blind Zone) | **2cm** (~1.2ms) | به‌خاطر Ring-Down فرستنده؛ زیر 2cm خوانده نمی‌شود |
| تاخیر داخلی Trig تا شروع برست | ~250~500µs (وابسته به نسخه) | روی عرض Echo اثر مستقیم ندارد |
| Crosstalk چند سنسور | فاصله‌گذاری ≥33ms بین سنسورها | تداخل آکوستیک/الکتریکی |

## ۶) زنجیره‌ی سیگنال داخلی (آنالوگ) 🔬

```
گیرنده R → [U2D: تقویت ×6] → [U2C: فیلتر میان‌گذر MFB] → [U2B: تقویت ×8] → [U2A+Q1: مقایسه‌گر هیسترزیس] → MCU (polling)
```
- نقطه‌ی کار خروجی اپ‌امپ: **2.4V** — آستانه‌ی پایین مقایسه‌گر: **1.4V** — آستانه‌ی بالا: **2.4V** — برش قله‌های مثبت: **3.4V**
- ⚠️ یافته‌ی مهم ریورس‌انجینیرینگ: فیلتر میان‌گذر در کلوئن‌های ارزان به‌جای 40kHz روی **~18kHz** تنظیم شده (خطای فابریک!) → حساسیت واقعی کمتر از حد طراحی است
- MCU به‌جای اینتروپت، **polling** می‌کند → گاهی پالس اول را می‌بیند و پالس دوم را می‌گیرد → خطای گامِ **+25µs** (یک پریود کامل)
- تشخیص فقط بر اساس **دامنه** است، نه فاز/الگوی 40kHz → اکوهای کاذب از نویز هم پذیرفته می‌شود
- وقتی هیچ مانعی نیست، «اکوهای کاذب تصادفی» با فاصله‌های به‌ظاهر منطقی گزارش می‌شود (رفتار واقعی و قابل شبیه‌سازی!)

## ۷) فیزیک انتشار صوت در هوا 🌡️ (مدل محیطی دوقلو)

### سرعت صوت (بازتولید واقعی):
```
v = 331.3 + 0.606 × T            (m/s، T به سانتی‌گراد، هوای خشک)
v ≈ 331.3 + 0.606T + 0.0124 × RH (تقریب با رطوبت نسبی RH%)
```
- دیتاشیت با **340m/s** حساب می‌کند (≈ 15°C) → در 20°C واقعی 343m/s است → خطای سیستماتیک ~1%
- ضریب دمایی: **~0.6m/s به‌ازای هر °C ≈ خطای 0.17% به‌ازای هر درجه**

### تضعیف (Attenuation):
- در 40kHz و 20°C / RH~50%: **~1.2dB/m** (تا ~1.4dB/m بسته به T/RH)
- رفت‌وبرگشت 4 متر = مسیر 8 متری → **~10dB افت فقط جذب**
- **اتلاف هندسی**: موج کروی → هر دوبرابرشدن فاصله **−6dB** (معکوس مجذور)
- جمعِ این دو عامل = دلیل واقعی محدودیت رنج و افت دقت در فواصل دور

### رفتار بازتاب از اجسام (خیلی مهم برای واقع‌گرایی):
| نوع مانع | رفتار |
|---|---|
| سطح صاف و سخت (شیشه/فلز/دیوار) | بازتاب قوی؛ رنج کامل 4m |
| سطح متوسط (چوب/پلاستیک) | بازتاب خوب |
| نرم (پارچه/اسفنج/موکت) | جذب امواج → اکوی ضعیف یا هیچ |
| آب/مایع | بازتاب عالی (کاربرد سنسور سطح مایع) |
| سطح زاویه‌دار | بازتاب آینه‌ای (Specular): زاویه‌ی انحراف > ~22° → اکو به سنسور برنمی‌گردد |
| اجسام کوچک | سطح مقطع کم → رنج مؤثر خیلی کمتر از 4m |
| توصیه‌ی دیتاشیت | سطح هدف **≥ 0.5m²** و تا حد ممکن صاف |
| آشوب (Multiple Reflections) | گوشه‌ها/راهرو → اکوهای چندگانه و فاصله‌ی اشتباه |

## ۸) مدل خطا — چیزی که دوقلو را «عین واقعیت» می‌کند 📊

| منبع خطا | بزرگی | نوع |
|---|---|---|
| دمای محیط | ~0.17% به‌ازای هر °C | سیستماتیک |
| رطوبت | ~0.03% به‌ازای هر 10%RH | سیستماتیک کوچک |
| Polling MCU داخلی (جاافتادن پالس اول) | گام‌های **+25µs ≈ +0.43cm** | سیستماتیک پله‌ای |
| آستانه‌ی دامنه‌ای مقایسه‌گر | جیتر بسته به شدت اکو (هدف دور/نرم → دیرتر قطع) | تصادفی |
| رفتار غیرمونوتونیک | خواندن‌ها همیشه با فاصله مرتب نمی‌شوند | تصادفی |
| رزولوشن تایمر MCU کاربر (micros() آردوینو) | 4µs ≈ 0.07cm | کوانتیزاسیون (سمت کاربر) |
| نویز الکتریکی | نیاز به دیکاپ 10~100µF روی تغذیه | تصادفی |
| اکوهای کاذب بدون مانع | فاصله‌های تصادفیِ معقول | رفتار ویژه |

*(نمونه‌ی واقعی از آزمایش David Pilling: 14697 خواندن پیوسته در فاصله‌ی ثابت → توزیع 447~471µs با ماکسیمم در 455~459µs → پراکندگی واقعی سنسور حتی روی هدف ثابت!)*

## ۹) Failure Modes و رفتارهای خاص ⚠️

1. **خارج از رنج**: پالس Echo به‌جای قطع شدن، **38ms** دوام می‌آورد → کد کاربر: `if(duration >= 38000) "Out of range"`
2. **زیر 2cm**: خواندن نامعتبر/نوسانی (Blind Zone)
3. **اکوهای کاذب**: در فضای باز بدون مانع، فاصله‌های تصادفی گزارش می‌شود
4. **Crosstalk**: دو ماژول هم‌زمان → خواندن‌های اشتباه متقابل
5. **Trig های نزدیک‌هم**: برست جدید روی اکوی قبلی سوار می‌شود → فاصله‌ی غلط
6. **اتصال داغ (Hot-Plug)**: بدون اتصال اول GND → عملکرد نادرست
7. **تغذیه‌ی ضعیف**: نویز چارج‌پامپ → نیازمند دیکاپ مناسب
8. **زوایای انحرافی**: مانع با زاویه > ~22° → «مانع نامرئی» از دید سنسور

## ۱۱) نگاشت مشخصات → معماری دوقلوی دیجیتال 🏗️
